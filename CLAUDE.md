# PathUp

Fitness and wellness app (training logger + guided programs + wellness check-in; nutrition and social later). CV flagship project for Denis. Users are 16+.

- Product, architecture, roadmap and asset docs live in `docs/` (Spanish). Read `docs/03-hoja-de-ruta.md` to know the current phase before starting work, and respect its "Fuera de alcance" list.
- UI copy in Spanish first (i18n keys, English later).
- Business logic goes in `src/domain/` as pure, tested functions.
- Run `npm run check` (lint, Prettier, tsc, Jest) before saying work is done; DB changes need a migration in `supabase/migrations` plus pgTAP tests (`npm run db:start && npm run db:test`, requires Docker Desktop).
- Docker Desktop on this PC does not start its engine, so pgTAP tests are verified in CI. Flow for a new migration: commit + push → CI green → `npx supabase db push` (project already linked) → `npm run db:types`.
- Tests use RNTL v14: `await render(...)`, `await user.press(...)`. Never put test files inside `src/app` (Expo Router would treat them as routes) and keep helpers in `src/test/`, not `__tests__/`. Screen tests use `renderRouter('./src/app')` and mock `@/features/auth/auth-provider` / `@/features/profile/profile-api`.
- After adding dependencies run `npm run lock:check`: npm on Windows can write a lockfile that `npm ci` rejects (fix: delete `node_modules` + `package-lock.json` and reinstall). Avoid packages whose peers clash with ESLint's `ajv@6` (that is why react-hook-form was dropped).
- If `tsc` complains about unknown routes, the typed routes in `.expo/types` are stale: start the dev server once to regenerate them.
- Routes are guarded in `src/app/_layout.tsx` with `Stack.Protected`: `(auth)` signed out, `onboarding` signed in without `onboarding_completed_at`, everything else signed in and onboarded. `privacidad` is public.
- Web preview: launch config `pathup-web` in H:/PROYECTOS/.claude/launch.json (port 8081).
- Never commit `.env.local`, the Supabase `service_role`/secret key or the database password.
- Images are AI-generated by us; raw files go in `assets/raw/` (ignored), optimized WebP in `assets/images/`, with tool/date/prompt logged in `assets/CREDITS.md`.
- Web build: `web.output: "static"` (custom shell in `src/app/+html.tsx`, only `/bienvenida` is pre-rendered), tree shaking forced by the flags in `.env`, PWA files in `public/`. Check the bundle with `npx expo export -p web` and serve it with `npx serve dist -l 3030` — the dev server does not hydrate, so hydration problems only show in that build.
- Icons: add them to `src/components/icons.ts` (deep imports); ESLint blocks importing `lucide-react-native` anywhere else and Jest maps both paths to the CommonJS build.
- App icons are generated by `node scripts/generate-icons.mjs` (placeholder until the real one is made with AI).
- "Probar sin cuenta" (public demo): the landing switches on demo mode (`src/lib/demo-mode.ts`, `src/features/account/demo.ts`) and the app runs as Marcos with sample data; in development `?demo=1` does the same. It is also the way to review signed-in screens without an account.
- Demo mode reads and writes `src/lib/demo-backend.ts` (8 weeks of workouts, routines, measurements, programme and check-ins in memory). Every new data API must branch on `isDemoMode()` the same way: the demo is public and must never touch the database (`src/__tests__/demo.test.tsx` fails if it does).
- Data that lives on the phone (offline queue, every snapshot, active workout) must be cleared by `forgetThisDevice` in `src/features/account/sign-out.ts`, used by sign-out, account deletion and the demo: another account can sign in on the same device.
- Progress, records and charts are pure functions in `src/domain/progress.ts` / `measurements.ts` over the downloaded history plus the offline queue (ADR 0006). Charts use `src/components/charts/line-chart.tsx` (react-native-svg) and `chartColors` from the tokens; validate any new chart colour with the dataviz palette validator.
- Routines store sets and rep ranges, never weights: starting one fills last session's values (ADR 0007).
- Guided programmes live in `src/data/programs.ts` (content) and `src/domain/programs.ts` (plan, next session, double progression). Progress is derived from the workouts themselves (`program_slug`, `program_session`), never stored (ADR 0008).
- The wellness check-in and the readiness score are pure functions in `src/domain/wellness.ts`; the session adjustment must stay small and always be skippable (ADR 0009).
- New image prompts: edit `docs/prompts/*.json` and run `node scripts/build-exercise-prompts.mjs <file>`; never edit the generated markdown by hand.
